# SigmaDesign：四组位姿生成对照实验与 A100 高吞吐优化

请在当前 SigmaDesign 项目中新建独立实验目录 `pose_generation_four_arm_comparison`，执行一次严格配对的四组对照，定位当前自主分子生成中严重碰撞、键长和键角异常的主要原因。

**本次任务重点是诊断 SigmaDock 位姿网络、预测化学图、动态连接更新和几何约束之间的关系，而不是立即重新训练模型。**

所有现有权重、历史结果、无水评价协议和原始生成代码均保持只读。

## 一、研究问题

当前冻结权重生成实验的结果为：

- 504 次生成中，网络终态 HQ 为 75/504（14.9%）。
- 刚性片段力场修复后为 406/504（80.6%）。
- 局部柔性修复后为 420/504（83.3%）。
- 原生输出存在明显的严重分子内碰撞、蛋白碰撞及连接几何异常。
- 仅对片段进行有限的刚性 T/R 优化，就能显著提高质量。

需要明确回答：

1. 原始 SigmaDock 对已知真实配体的 docking 能力是否依然正常？
2. 自主预测的化学图是否导致位姿预测能力下降？
3. 扩散过程中反复更新片段身份或连接关系，是否破坏已有的合理构象？
4. 在不重新训练 SigmaDock 的情况下，几何引导能否直接改善网络终态质量？
5. 主要问题究竟是跨片段键长/键角、分子内碰撞、蛋白碰撞，还是多个问题共同造成？

不能只根据最终 HQ 改善推测原因，必须设计配对对照。

## 二、四组实验设计

| 组别 | 化学图 | 扩散过程 | 几何约束 |
|---|---|---|---|
| A：Oracle Docking | PDBBind/CASF 真实配体图 | 固定真实图 | 无新增引导 |
| B：Predicted Fixed Graph | SigmaDesign 预测的合法图 | 从开始到结束固定图 | 无新增引导 |
| C：Predicted Dynamic Graph | SigmaDesign 预测的合法图 | 按当前协议动态更新图 | 无新增引导 |
| D：Predicted Fixed + Guidance | 与 B 完全相同的预测图 | 全程固定图 | 扩散中增加几何引导 |

### A 组：验证原始 SigmaDock 能力

使用已知蛋白–配体复合物，向 SigmaDock 提供真实化学图和片段身份，但不得将真实结合位姿直接作为待去噪状态或初始答案。

执行官方原生去噪。

记录：

- Docking RMSD；
- RMSD < 2 Å 成功率；
- 跨片段键长、键角；
- 分子内碰撞；
- 蛋白碰撞；
- HQ_no_water；
- MMFF 修复前后变化。

重点判断原始 SigmaDock 在熟悉任务中的位姿能力是否保留。

真实配体信息只用于 A 组的 Oracle 化学图和合法评价，不得泄漏到 B/C/D 的预测图、初始坐标或几何引导中。

### B 组：预测图固定去噪

使用当前冻结身份模型、TimeConnectionPredictor 和 hierarchical_search，生成片段身份与合法连接图。

在首次确定完整合法化学图后，冻结：

- 片段数量 N；
- 片段身份；
- 连接原子；
- 键级；
- 立体定义。

此后不再重新预测或改变拓扑。

使用原始 SigmaDock，在完整化学图条件下执行 24 步去噪。

记录未经任何力场修复的终态质量。

### C 组：预测图动态更新

严格复现 `2611/1105/1345_diversity` 中的动态联合生成协议。

保持当前：

- 片段身份采样策略；
- TimeConnectionPredictor；
- hierarchical_search；
- 连接更新时机；
- 合法化学图重建；
- 参考形状转移；
- 更新接受/拒绝规则；
- SigmaDock 24 步去噪。

优先采用历史冻结方案中步数 5、10、15、20 的连接更新协议。

记录每次更新前后的：

- 化学图变化；
- 连接端口变化；
- 片段位置和朝向；
- 跨片段键长；
- 跨片段键角；
- 原子碰撞；
- 位姿变化量；
- 接受或拒绝原因。

必须区分网络原生运动、图变化造成的坐标转移以及后处理的贡献。

### D 组：预测图固定 + 几何引导

D 组使用与 B 组完全相同的：

- N；
- 片段类型；
- 合法连接图；
- 初始 T/R；
- 口袋；
- 随机种子；
- SigmaDock 预训练权重。

区别只在于扩散过程中增加几何约束。

使用以下能量：

`E_geometry = λ_b * E_bond + λ_a * E_angle + λ_r * E_nonbonded + λ_p * E_protein_clash`

其中：

- E_bond：跨片段共价连接键长度误差；
- E_angle：跨片段连接附近键角误差；
- E_nonbonded：跨片段非键原子排斥，排除 1–2、1–3 邻居；
- E_protein_clash：与蛋白非水原子的严重空间重叠惩罚。

键长参考使用 MMFF94s 根据完整预测化学图确定的平衡值。

键角参考优先使用预测化学图可确定的力场平衡几何。不能读取真实配体构象中的角度。

对当前片段 T/R 计算几何能量梯度，使用受限的小幅 SE(3) 修正，再继续 SigmaDock 去噪。

**几何引导必须作用于扩散轨迹，而不是扩散结束后再调用一次 MMFF 修复。**

优先在扩散中后期开启引导，建议使用 t ≤ 0.3 作为初始方案。具体权重、步长和开启时间只能在开发集选择，不能根据正式测试集优化。

避免强制投影到精确平衡键长，防止出现过度修正和蛋白碰撞。

D 组不加载 A4 独立几何头，不修改 SigmaDock 权重。

## 三、公平比较与配对条件

首轮使用已有的 6 个诊断口袋：

`12AV、7ILZ、9RT3、9SYL、9T4A、9T51`

每口袋 12 个随机种子。

B、C、D 共用同一份初始片段身份、N、起始合法图、初始 T/R 和相同的模型随机噪声流。

B/D 的连接图必须逐原子、逐键一致。

C 仅允许预先定义的动态连接更新产生差异。

需要注意：

**A 组使用真实配体化学图，与 B/C/D 的生成分子未必具有相同原子数或化学结构，所以 A 组是官方 docking 能力参照，不是严格逐分子配对的生成质量比较。**

必须将以下两类比较分别报告：

1. A 的真实图 docking 表现与原始官方基线比较；
2. B/C/D 在相同预测图和初始化条件下的配对比较。

不得将 A/B 质量差直接归因于位姿网络，因为二者同时存在化学结构分布差异。

如条件允许，增加一个未参与开发和调参的独立口袋集合进行最终验证。

## 四、A100 性能要求：必须实现真正的批量推理

本次特别要求提高 A100 的有效利用率。

**禁止正式测试沿用“一个样本完成全部 24 步，再启动下一个样本”的串行低吞吐实现，除非实际基准测试证明批量实现不可行或更慢。**

### 1. 先审计瓶颈

使用 PyTorch profiler、CUDA profiling 或等价方式，统计：

- GPU 神经网络前向耗时；
- 连接搜索 CPU 耗时；
- RDKit 分子构建耗时；
- 化学图转换耗时；
- NativeState 初始化和更新耗时；
- GPU↔CPU 数据传输；
- 几何引导梯度计算；
- 质量评价和磁盘写入。

识别 GPU 空闲的实际原因。

不能仅通过 `nvidia-smi` 利用率判断模型计算效率。

### 2. 实现批量 SigmaDock 推理

优先使用 PyTorch Geometric Batch 将多个不同分子的蛋白–配体图组织成 batch。

每个 batch 共享相同扩散时间网格，分别保留每个分子的：

- 原子索引偏移；
- 片段索引偏移；
- 动态图；
- T/R；
- 独立随机数状态；
- 生成结果；
- 更新日志。

每个扩散时间步：

1. 将 batch 中的多个分子一次送入 GPU。
2. 批量执行 SigmaDock 网络前向。
3. 分别更新各分子的片段状态。
4. 处理需要更新拓扑的样本。
5. 在下一时间步重新组织或维护有效 batch。

避免 Python 循环逐样本调用 GPU 神经网络。

注意所有动态边、片段质量、惯性、坐标和方向索引必须严格正确，不能为了 batch 化改变模型数学含义。

### 3. 自动确定合适 batch size

先测试 batch size：

`1、4、8、16、32`

根据显存占用、吞吐量和模型实际运行情况，选择最优设置。

A100 的具体显存容量以运行时检测为准，不允许假定所有机器都是 80 GB。

建议：

- 自动检查 GPU 剩余显存；
- 按蛋白原子数、配体原子数及图边数量分桶；
- 设置安全显存余量；
- OOM 时拆分 batch 并记录；
- 使用预热后的 GPU throughput，而不是只比较首次启动耗时。

如 batch=16 比 batch=8 更慢，必须采用实际吞吐更高的配置。

### 4. CPU 与 GPU 流水线并行

将 CPU 连接搜索、RDKit 化学图处理和质量评价与 GPU 神经网络计算解耦。

建议使用：

- CPU worker 池并行处理独立化学搜索任务；
- 预先准备合法连接候选；
- 预先缓存不变的蛋白图和片段模板；
- pinned memory 与非阻塞数据传输（适用时）；
- GPU 持续执行已有 batch；
- CPU 在后台准备下一批待推理样本；
- 生成完成后异步执行 CPU 质量评价和文件写入。

注意不要使用不安全的 CUDA fork 方式，也不要让多个 worker 无必要地重复加载完整 SigmaDock GPU 模型。

只有实际 profiler 证明有效时才启用复杂的 CUDA streams、CUDA graphs 或 torch.compile。

### 5. 混合精度和数值稳定性

A100 可以尝试 BF16 autocast 提高主干网络吞吐。

但必须先与 FP32 对照，确保：

- SO(3) 旋转矩阵保持数值稳定；
- SE(3) 更新没有明显数值漂移；
- 几何引导梯度稳定；
- 键长、键角计算精度足够；
- HQ 和碰撞结果不因混合精度发生不可接受的变化。

关键的旋转指数/对数、微小距离、力场相关计算可保留 FP32。

不能为了速度悄悄降低质量标准。

### 6. 需要梯度与不需要梯度的部分分开

A/B/C 组使用冻结权重推理，关闭不必要的 autograd。

D 组仅对当前片段 T/R 建立几何能量梯度，不对冻结的 SigmaDock 网络参数反向传播。

不要把整条 24 步扩散轨迹保留为训练计算图。

可以在每一步把网络输出与需要梯度的几何引导部分明确隔离，以减少显存和计算开销。

### 7. 性能必须有量化结果

记录：

- batch size；
- 显存峰值；
- GPU 模型前向吞吐；
- 完整分子生成吞吐；
- 每个分子的平均 GPU 前向次数；
- CPU 搜索时间；
- CPU 质量评价时间；
- GPU 空闲比例；
- 加速前后 wall time；
- A/B/C/D 各组完整运行成本。

正式运行前输出一个 `PERFORMANCE_BENCHMARK.md`。

若实际推理仍然逐样本调用神经网络，必须明确记录原因，不能简单声称已做批处理优化。

### 原生质量和修复质量必须分开

分别保留：

1. `native_final`：最后一次神经网络/几何引导更新后的输出。
2. `rigid_repair`：独立刚性 MMFF 修复后的输出。
3. `local_flex_repair`：独立局部柔性修复后的输出。

修复仅用于诊断，不参与原生 HQ 计分。

D 的扩散中几何引导属于其生成过程，必须另行记录引导前后的变化，不能将其与 B/C 的纯神经终态混为同一类“无约束原生输出”。

## 六、额外的因果诊断

### 1. B 与 C：动态连接是否伤害位姿？

按每一步比较：

- 相同初始图下的构象；
- 动态图是否发生改变；
- 改图前后是否增加碰撞；
- 坐标参考转移是否造成大幅位移；
- 修改图后剩余去噪步数是否足够。

区分：

- 化学图发生变化本身；
- 图重建导致的参考坐标变化；
- 后续 SigmaDock 运动的影响。

不能将所有变化直接归因于神经网络。

### 2. B 与 D：几何引导是否有效？

在完全相同的化学图和初始 T/R 条件下，比较：

- 键长改善量；
- 键角改善量；
- 分子内碰撞改善量；
- 蛋白碰撞改善量；
- HQ 改善量；
- 引导造成的整体位姿偏移；
- 额外 GPU 时间。

特别检查：是否出现键长变好但碰撞变差。

### 3. A 与 B：分布偏移还是官方模型失效？

A 组必须验证原始 SigmaDock 的已知配体 docking 基线。

如果 A 组正常、B 组明显变差，则后续重点检查：

- 自主预测化学图与预训练分布的差异；
- 虚拟连接键和原始图表示是否一致；
- 片段模板、端口及惯性计算；
- 图构建接口；
- 网络是否真正读取跨片段连接信息。

不能直接认定需要重新训练整个 SigmaDock。

## 七、分阶段执行，不允许逐个样本慢速跑正式任务

执行顺序：

**阶段 0：输入与接口审计**

确认图构建、随机种子、原始权重、质量协议和已知基线一致。

**阶段 1：批量性能基准**

用少量样本测试 batch=1/4/8/16/32。

必须先完成批处理一致性检查，确保与原串行实现的结果在合理数值容差内一致。

**阶段 2：小规模四组预检**

使用少量口袋和种子同时运行 A/B/C/D，确认结果、几何引导、梯度、日志和分母正确。

这一步只用于程序核验，不用于最终比较。

**阶段 3：正式测试**

执行六个诊断口袋 × 十二个种子。

B/C/D 使用严格配对输入，按批次完成，不进行逐样本串行推理。

A 组使用能够提供可靠真实配体参考的对应口袋和合法样本；不满足 Oracle docking 条件的样本明确标记，不编造 RMSD。

不得为了让实验快速完成而减少预定种子、跳过失败样本或放宽 HQ 标准。

**阶段 4：独立验证**

若已有独立口袋集合且数据许可，使用冻结参数运行相同的对照，验证诊断结论是否能推广。

若没有，明确报告当前六口袋属于已查看诊断集合，不宣称独立泛化结论。

## 九、最终必须回答的研究问题

1. 原始 SigmaDock 的 Oracle docking 性能是否正常？
2. 预测图固定去噪是否已经产生严重碰撞？
3. 动态更新连接是否进一步破坏构象？
4. 几何引导能否在不微调权重的情况下提高 HQ？
5. 引导主要改善键长、键角、分子内碰撞还是蛋白碰撞？
6. 哪些错误只通过刚性片段修正就可以解决？

不要直接启动大规模训练，也不要改变任何历史模型权重或实验结果。
